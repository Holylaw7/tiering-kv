# AI 代码审查规则（CODE_REVIEW_RULES）

> 适用范围：所有提交 develop / main 前的代码审查；AI 与人工共用同一套门禁。

## 1. 审查时机

- 每个任务完成、提交前：自审；
- 每个 feature 分支合并前：正式审查；
- 关键模块（并发、存储、网络）每次变更：专项审查。

## 2. 必查清单

- **正确性**：边界条件、空值、溢出、编码/解码往返、异常路径；
- **并发**：竞态、可见性、死锁、锁顺序、队列背压、线程池饱和；
- **性能**：事件循环无阻塞、热路径无全局锁、避免隐式装箱/复制、IO 异步化；
- **质量**：SOLID、无巨型类、无魔法数字、关键算法注释、异常处理完整；
- **测试**：变更伴随单元/集成/压力测试，遵循 TDD；
- **文档**：README / Architecture / ADR / CHANGELOG 是否同步；
- **Git**：Conventional Commit、无调试残留、无无关文件。

## 3. 审查流程

1. 自审（对照清单）；
2. AI 审查：检查 diff、运行测试、静态扫描（后续引入 SpotBugs/Checkstyle）；
3. 修复问题并补充测试；
4. 重新运行 `mvn test` 与相关压测；
5. 合并前确认无未解决 comment、工作树干净。

## 4. 门禁（硬性）

- `mvn test` 必须通过；
- 核心模块变更必须有对应测试；
- 架构级变更必须附 ADR；
- 文档不同步视为阻塞项。
