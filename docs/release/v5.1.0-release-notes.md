# Tiering-KV v5.1.0 Release Notes

- 发布日期：2026-10-28
- 类型：功能修复（冷热分层读路径）+ 容量模型
- 对应决策：ADR-0361 · 技术债：TD-086 关闭、TD-084 给出模型

## 修复：迁移后的数据现在能读回来了（TD-086）

修复前（60 万确定性键、128MB 引擎上限）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 读回命中率 | **51.92%** | **100.00%** |
| `DBSIZE` | 311,539（仅热层） | **600,000（精确）** |
| 读吞吐 | 24,246 ops/s | **35,246 ops/s** |
| 读延迟 P50 / P95 | 0.125 / 0.308 ms | **0.100 / 0.183 ms** |

根因：迁移只写冷层，主读链从不查询冷层——表现为"超配即丢数据"。

改动：

- `ColdStorageEngine`：新增 `entry(key)`（暴露 TTL）与 `liveCount()`（惰性精确计数）；
- 新增 `TieringReadStorageEngine`：`get/exists` 冷层回退、`delete` 双删防复活、
  `size` 汇总两层、`iterator` 归并去重（热层优先）；
- 原子写 copy-up：`INCR/APPEND/GETSET/GETDEL/UPDATE` 前回填冷层值并保留 TTL，
  `SETNX/TTL/EXPIRE/PERSIST` 感知冷层；
- `DBSIZE`/`SCAN`/`FLUSHALL` 随之覆盖冷层。

## 容量模型（TD-084）

边际每键开销实测（剔除一次性段分配）：

| 值大小 | 每键计量 | 固定开销 | 1GB 可容纳 |
| --- | --- | --- | --- |
| 100 B | 174.9 B | 74.9 B | 约 614 万键 |
| 1 KB | 1,098.4 B | 74.4 B | 约 98 万键 |
| 10 KB | 10,313.8 B | 73.8 B | 约 10.4 万键 |

公式：**每键字节 ≈ 值大小 + 74 B**；`可容纳键数 ≈ memory.limit / (valueSize + 74)`。

## 已知限制

- `DBSIZE` 写入后首次查询触发一次冷层全量扫描（60 万键约 0.2–0.5s）；
- `SCAN` 覆盖冷层后首次扫描成本上升；
- `WATCH`/`versionOf` 仍只反映热层版本；
- 冷层读命中不回填热层（无读触发写压力）。
