## 核心变更

### 1. 零分配 RESP 编解码、Linux 原生 Epoll 与分片调度去争用（B1）
- **零分配 RESP 协议栈（`tiering-protocol`）**：
  - `RespDecoder` 采用零拷贝 `readAsciiLong`、`ByteProcessor.FIND_CR` 与无栈单例 `IncompleteInputException` 彻底消除解码期临时 `String` 与异常栈分配；
  - `RespEncoder` 预编码常用静态帧（`+OK` / `+PONG` / `+QUEUED` / `$-1` / `*-1` / `_` / `:0..1024` / 小 Bulk 头）与 `writeAsciiLong`；`RespRequestParser` 对热 ASCII 命令做零分配驻留，`CommandEngine` 增加 `isLowerAscii` 快路径与 `COMMAND_KEYS` 缓存。
- **Netty 传输与流水线优化（`tiering-server`）**：
  - 引入与现有 Netty BOM 同版本（`4.1.137.Final`）的 `netty-transport-native-epoll`（`linux-x86_64` & `linux-aarch_64`，经 Trivy 验证保持 `0` CVE 例外），`NettyTransportFactory` 在 Linux 自动启用原生 Epoll、Windows/macOS 自动回退 NIO（支持 `-Dtieringkv.transport=nio` 显式覆盖）；
  - `TieringKvServer` 启用 `PooledByteBufAllocator.DEFAULT`、`SO_BACKLOG=4096` 与 `WriteBufferWaterMark`；`ConnectionInitializer` 接入 `FlushConsolidationHandler(256, true)`；`CommandHandler` 改用 `channelReadComplete` 批冲刷与原始 `long[]` 计时环；`ResponseSequencer` 采用 256 槽无锁环形缓冲 + 稀疏溢出回退。
- **高并发调度器消除全局竞争**：
  - `KeyShardExecutor` / `ShardWorker` / `ShardQueue` / `ConcurrencyMetrics` / `ShardRouter` 消除全局 `AtomicInteger active` 热点（改用每分片 `LongAdder` + 单写 `AtomicLong`）、支持 `drainTo(64)` 批量消费与 2 的幂位掩码路由，彻底根治 `c=200` 并发吞吐倒挂（回环实测 `c=50 81.4k/84.8k → c=200 91.7k/92.2k rps`，`c=50, P=16` 达 `651k/681k rps`）。

### 2. 24-bit 内联 Morris-LFU、SkipList 瘦身与 Generational ZGC（B2）
- **零额外字段内联 LFU**：在 `KeyValueEntry` 原有对象对齐间隙中内联 Redis/Valkey 风格 24-bit 热度状态（16-bit 衰减时间槽 + 8-bit Morris 对数频次，`LFU_INIT_VAL=5`），99%+ 热读零 `volatile` 写；
- **默认采样淘汰策略**：新增 `SampledLfuPolicy` 作为默认淘汰策略（`cache.eviction-policy: sampled-lfu`，`tracksViaAccessEvents() == false`），`TrackingStorageEngine` 跳过 `AccessEvent` 分配与全局锁争用；`MemTable` 新增 `putOwned()` 与 256-bit 位图去重 `sampleLiveEntries()`；`SkipList` 动态维护 `currentMaxLevel`、复用 `updateBuffer` 并以单指令 `numberOfTrailingZeros` 生成随机层高；`SegmentLFUPolicy` 增加有界事件缓冲上限（`65,536`）；
- **容器默认 Generational ZGC**：`deploy/Dockerfile` 与 `deploy/console/docker-compose.yml` 启用 JDK 21 `-XX:+UseZGC -XX:+ZGenerational -Dio.netty.allocator.type=pooled`（支持 `JAVA_OPTS` 环境变量覆盖与 `exec` PID-1 启动）；
- **同机同 JVM 实测收益**：63 万键 × 64B 存活堆从 `504.0 MB` 骤降至 **`174.0 MB`（-65.5%）**，8 线程并发读吞吐从 `472k` 跃升至 **`4.31M ops/s`（`9.13×`）**。

### 3. WAL Group Commit、16 分片 S3-FIFO 与零除法冷层加速（B3）
- **WAL Leader-Follower Group Commit**：`WALManager` / `WALWriter` 锁外并行编码与 CRC32C 校验，并发写按最多 `64` 条 / `256 KB` 合并为单次顺序写 + 单次 `force()` 刷盘（16 线程 `fsync=ALWAYS` 实测合并 `avgBatch=12.31` writes/fsync，刷盘次数减少 `91.9%`，崩溃恢复 100% 一致）；
- **16 分片 S3-FIFO BlockCache**：`BlockCache` 升级为自适应 16 分片 SOSP'23 S3-FIFO（Small 10% + Main 90% + Ghost，小容量 `<32` 自动单分片保兼容），2,000 个扫描块冲击下热点块存活 **`120/120`（100%）**；
- **并发冷读与零除法 BloomFilter**：`ColdStorageEngine` 升级 `ReentrantReadWriteLock` + `ConcurrentHashMap<Long, SSTableReader>` + 后台无锁 `refreshLiveCount()`，8 线程并发冷读达 **`115k ~ 136k ops/s`（命中率 `99.90%`）**；`BloomFilter` 采用零除法 FastRange（`0.4150%` FPR，`165.2 ns/probe`）；`Block.findEntry` 支持块内原地零全量解码查找。

### 4. HNSW 零装箱扁平图、SQ8 标量量化与可插拔 FMA/SIMD 距离核（B4）
- **图布局与搜索路径重构（`tiering-storage`）**：`HnswIndex` 邻接表重构为扁平原始 `int[][]` + `int[] neighborCounts`，写入预计算单位归一化向量；上层执行零分配 1-NN 贪心下降，层 0 使用 `ThreadLocal<SearchWorkspace>`（代数标记 `visitedGen[]` + 原始类型小/大根堆 `IntFloatMinHeap`/`IntFloatMaxHeap`）；
- **可插拔距离核与 SQ8 量化**：新增 `VectorDistanceKernel`（默认 4 路展开 `ScalarFmaKernel` + 运行时安全探测 `jdk.incubator.vector` 模块 + 支持自定义内核注入）与 `ScalarQuantizerSq8`（支持 `QuantizationMode: NONE | SQ8 | SQ8_RERANK`）；升级 `TKHN` v2 序列化格式并 100% 兼容旧 `TKHN` v1 反序列化；`VectorIndexStore` 新增 `rebuildIndex(QuantizationMode)` 重载；
- **实测收益**：`HnswSearchBenchmarkTest`（20K×64D）`P50 0.473 ms → 0.133 ms`（`3.56×`）、`P99 0.847 ms → 0.322 ms`（`2.63×`）；`SQ8` 模式向量内存下降 **`69.1% ~ 75%`**、序列化体积缩减 **`48% ~ 59%`**，`SQ8_RERANK(ef64)` 在 2K×64D 实测 **`Recall@10 = 0.9700`**。
