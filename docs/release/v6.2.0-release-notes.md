- 发布日期：2026-11-26
- 类型：控制面差异化升级（多模型工作台 + 分布式集群拓扑 + K8s Operator 零依赖桥接 + 多副本冷启动加固）
- 容器镜像（GHCR，4 套全量发布）：

  - `ghcr.io/holylaw7/tiering-kv-operator:v6.2.0`（Kubernetes Operator 控制器）
  - `ghcr.io/holylaw7/tiering-kv-console-server:v6.2.0`（控制面后端，多模型 API + 拓扑/K8s 零依赖桥接 + Flyway 咨询锁加固）
  - `ghcr.io/holylaw7/tiering-kv-console-web:v6.2.0`（控制面前端，`/#/multimodel` 多模型工作台 + `/#/topology` 集群拓扑与云原生控制页）

## 核心变更

### 1. 控制台多模型工作台（`/#/multimodel`，C1）
- **底层协议与内核落盘打通**：
  - `RespCodec` 兼容 Tiering-KV RESP2 对 `RespDouble` 的 `:0.95\r\n` 编码及 RESP3 `,` 浮点 / `_` Null 帧，无缝解析 `VECTOR.SEARCH`、`TS.RANGE`、`TS.MRANGE` 与 `TS.REDUCE` 真机返回；
  - `Main.java` 为单机 `VectorCollectionRegistry` 接入 `configureCheckpoint(vectorDir)`，支持在线执行 `VECTOR.CHECKPOINT` 原子落盘。
- **控制面多模型服务与 API（`/api/v1/multimodel/**`）**：
  - **Vector HNSW**：集合列表与总数（`VECTOR.LIST`）、写入向量（`VECTOR.ADD`）、Top-K 相似度检索与耗时统计（`VECTOR.SEARCH`）、条目/集合删除与物理索引落盘（`VECTOR.DEL`/`DROP`/`CHECKPOINT`）；
  - **TimeSeries**：自动发现全部时序键（`TS.MRANGE`）、写入与增量累加（`TS.ADD`/`INCRBY`）、范围查询与 `AVG/SUM/MIN/MAX/COUNT/FIRST/LAST` 桶降采样及全序列 `TS.REDUCE`；
  - **JSON Path Explorer**：`SCAN + TYPE=json` 键发现、JSONPath 查询（`JSON.GET`/`TYPE`/`OBJKEYS`）、原地写入/删除/数值自增/数组追加；
  - 全部写操作受 `ADMIN`/`OPS` RBAC 鉴权与 `AuditService` 留痕保护；连接普通 Redis 时优雅返回 `supported=false` 提示。
- **前端 `MultiModelView.vue`**：三大专业页签（Vector HNSW 相似度条、TimeSeries ECharts 6 交互式折线图、JSONPath 字段下钻与原地编辑）。

### 2. 分布式集群拓扑与 K8s Operator 零依赖桥接（`/#/topology`，C2）
- **集群拓扑与 16384 HashSlot 解析（`/api/v1/cluster/topology`）**：`ClusterTopologyService` 实时解析内核 `# Cluster`、`# Transaction`、`# Persistence` 段落，精确计算 16384 槽位在各 Region 的分配比例，单机实例自动呈现 `STANDALONE` 视图。
- **纯 JDK 21 K8s Operator 无依赖桥接（`/api/v1/cluster/k8s/**`）**：`K8sOperatorBridgeService` 严格采用 **JDK 21 `java.net.http.HttpClient` + Jackson 3**（零 Fabric8 / Jackson 2 传递依赖），直连 `tieringkv.io/v1/tieringkvclusters` CustomObjects API，支持列举集群状态、在线扩缩容（`storageReplicas`/`gatewayReplicas`/`metadataReplicas`）、滚动升级 `spec.image` 与 CR 注解触发按需备份 Job；未接入 K8s 时返回 `enabled=false` 优雅降级。
- **前端 `TopologyView.vue`**：ECharts 6 16384 HashSlot 柱状图 + Region 节点表 + Percolator 2PC 实时事务面板 + K8s Operator 生命周期控制卡片。

### 3. 多副本冷启动加固与第 8 组全栈 E2E（C1/C3）
- **Flyway 多副本冷启动 MySQL 咨询锁**：新增 `FlywayConfig`，在连接 MySQL/MariaDB 时以会话级咨询锁 `GET_LOCK('tiering_console_flyway_migrate', 60)` 串行化首次建表与迁移（H2 透传），彻底根治双副本同毫秒冷启动引发的 `flyway_schema_history already exists, and is empty` 竞态；
- **第 8 组 Playwright E2E 规范**：新增 `console-web/e2e/multimodel-and-topology.spec.ts`，实测覆盖 Vector HNSW 写入/检索/落盘、TimeSeries 查询与曲线渲染、JSONPath 文档新建与下钻以及 `/#/topology` 16384 槽位图表与 K8s 优雅降级状态。

## 升级说明

- **数据库**：与 `v6.1.0`（Flyway V11）完全兼容，无新增表结构变更；多副本首次冷启动自带 MySQL 咨询锁保护。
- **K8s 桥接启用**：在 Kubernetes 部署控制台时，设置 `CONSOLE_K8S_ENABLED=true` 并配置命名空间与 `TieringKVCluster` RBAC 即可启用页面级扩缩容/升级/备份操作。
