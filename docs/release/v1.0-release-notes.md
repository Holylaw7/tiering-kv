# Tiering-KV v1.0 Release Notes

2026-08-11 · Phase 24 Cloud Native Production Release

## 定位

Redis 协议兼容的 LSM 冷热分层 KV 存储引擎，叠加 Multi-Raft 分布式集群与
Percolator 分布式事务（MVCC + 2PC）。

## 能力清单

- RESP2 协议 + Redis 命令模型（SET/GET/DEL/EXISTS/PING/ECHO/MSET 等价）；
- 冷热分层存储：MemTable（256 段 SkipList）→ WAL → SSTable → Compaction →
  自动 Flush/Migration + 背压；
- 淘汰与热度：LFU（decay）+ ARC + Bloom Filter + Hot Key 治理；
- IO 优化：mmap 零拷贝冷读 + Block Cache + Off-Heap Memory Pool；
- 分布式：16384 slot 路由、Multi-Raft（Region 组）、持久化 Raft 日志 +
  快照、批量/流水线复制、在线迁移、TLS/HMAC 安全 RPC；
- 事务：MVCC 多版本、HLC 时间戳、Percolator 2PC、锁解析、生命周期
  TTL/心跳、崩溃恢复；
- 生产运行：gateway/coordinator/participant/metadata 独立角色、健康探针、
  优雅停机、备份恢复、滚动升级、Kubernetes 清单、CI 容器 E2E 工作流。

## 质量与性能

- 全量测试：**2238/2238 全绿**（Phase 1–24，含单元/集成/混沌/基准）；
- 事务 SET：144–175K ops/s；跨区事务：45–83K txn/s；
- Leader failover：164–303ms；事务恢复：≈3ms；
- 存储层 GET P99 ≈2.5μs；网络端到端 GET P99 ≈0.19ms（Phase 2/9 口径）。

## 已知限制（如实声明）

- 教学/工程级实现，不宣称生产级 Redis 替代品；
- 元数据 Multi-Raft 为进程内传输，跨机网络化待验证（TD-050）；
- 真实 Docker 磁盘混沌与 CI 容器 E2E 待 Linux Runner 执行（TD-048/049）；
- pub/sub、Lua、RESP3、内存降低 60–80% 正式基线为后续版本方向。

## 升级建议

从 v0.1.0（Phase 23）升级：

1. 备份元数据快照与 MVCC 索引；
2. 滚动升级逐节点替换（保持 quorum ≥2）；
3. 升级后执行 `recover()` 补完决策；
4. 通过 `/readiness` 确认 leader 就绪后再放流量。
