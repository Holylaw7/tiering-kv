# Phase 13 分布式优化基准报告

Phase 13 · 2026-08-10

环境：本机 Windows 11，JDK 21.0.12（编译目标 17），20 核，`-Xmx1g`；
网络 127.0.0.1 TCP 回环，日志 FileRaftLog ASYNC。

## 1. Raft 批量/流水线复制

3 节点 TCP 集群，`maxBatchEntries=256`、`flushInterval=1ms`、
`maxInflight=16`，64 并发写入者 × 80 条：

| 指标 | Phase 12（串行同步） | Phase 13（批量 + 流水线） |
| --- | --- | --- |
| 吞吐 | 700–1,359 ops/s | **22,169 ops/s** ✅（目标 >5000） |
| P50 / P95 / P99 | 0.65 / 1.24 / 2.16 ms（单写者） | 2.50 / 4.32 / 7.80 ms |
| 复制滞后 | <1ms | 0ms |

结论：批量 + 流水线 + group commit + 空闲即刷（idle flush）使吞吐提升
约 16 倍并达成 >5000 ops/s；顺序写路径无回退（本机集群单写者
104–210K ops/s）。

## 2. 游标迁移

| 负载 | Phase 12（每批重建快照） | Phase 13（游标单次扫描） |
| --- | --- | --- |
| 200K × 100B | 16–20MB/s | 17.7MB/s |
| 200K × 1KB | — | **216–245MB/s** ✅（目标 >100MB/s） |
| 断点续传（180K 剩余） | 349–549ms | 755–856ms |

结论：游标模型消除了重复快照扫描；单条 `MemTable.put` 固定开销使小
负载（100B）仍受限于条目速率（约 180K entries/s），大负载（1KB）突破
100MB/s。批量写接口是下一阶段优化点。

## 3. RPC 安全开销（10K 顺序调用）

| 模式 | 单次调用 | TLS + 认证开销 |
| --- | --- | --- |
| 明文 | 142–164 μs | — |
| TLS + Token 认证 | 229–279 μs | +50–70% |

结论：安全层增加约 0.1ms/调用（握手分摊后），可接受。

## 4. 元数据 Raft

| 指标 | 结果 |
| --- | --- |
| 顺序写吞吐（2K 条命令） | 69–104K ops/s |
| leader 故障转移 | **115–290ms**（目标 <5s ✅） |

结论：空闲即刷优化后元数据顺序写不再受 flush 周期约束；故障转移
满足可用性目标。

## 5. 瓶颈分析

- 复制：单写者路径由空闲即刷保证低延迟；高并发下批量/流水线生效
  （64 写者 22K ops/s）；
- 迁移：`MemTable.put` 单条成本主导小负载吞吐，游标消除扫描开销；
- RPC：TLS 握手与加解密带来 66% 单调用开销；
- 元数据：顺序写受 flush 周期约束，故障转移开销可忽略。
