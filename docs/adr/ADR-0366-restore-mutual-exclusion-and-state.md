# ADR-0366：恢复互斥与恢复状态机

- 状态：Accepted
- 日期：2026-11-07
- 关联：ADR-0365（备份恢复语义）、TD-101（并发备份）、G0-1

## 背景

`BackupService.restore()` 是控制面唯一会**批量改写用户数据**的操作，但它在实现上没有任何并发保护：

```java
public long restore(Long recordId) {
    ...
    for (String line : Files.readAllLines(file, UTF_8)) {
        restoreEntry(instance, entry);   // DEL + SET，逐条覆盖
    }
}
```

与 `export()` 对比：导出在第 103 行用按实例锁把"检查 + 落库"合并为临界区（TD-101 的修复），
而恢复既没有锁，也没有"进行中"状态。后果有三：

1. 同一实例并发两次恢复，两条回放流交错，最终数据取决于线程调度；
2. 恢复与导出并发，导出可能抓到"半恢复"的数据；
3. 恢复中途失败时，调用方只知道抛了异常，不知道已经写进去多少键，
   且备份记录的状态仍是 `SUCCESS`（因为恢复结果从来无处记录）。

## 决策

### 1. 状态与备份状态分离

新增 `RestoreStatus{NONE, RESTORING, SUCCEEDED, FAILED}`，写在 `backup_record.restore_status`，
**不复用** `status`。理由：`status` 描述"备份文件是否可用"，若把恢复失败写进 `status`，
一次失败的恢复会让一份完好的备份看起来也坏了，用户会误删。

新增字段：`restore_started_at`、`restore_finished_at`、`restored_keys`、`restore_message`。

### 2. 实例级互斥（跨操作）

互斥不靠内存锁的持有时间，而靠**可持久化的状态**，这样多控制面实例部署时同样成立：

| 操作 | 检查 | 结果 |
| --- | --- | --- |
| restore | 该实例存在 `RESTORING` 记录 | 409 |
| restore | 该实例存在 `RUNNING` 备份 | 409 |
| export | 该实例存在 `RESTORING` 记录 | 409 |
| export | 该实例存在 `RUNNING` 备份 | 409（TD-101 既有行为） |

内存中的按实例锁仍然保留，但只用于"检查 + 标记"这一小段临界区，不覆盖回放过程。

### 3. 异常安全

- 回放前先落库 `RESTORING`，让其他请求可见；
- 成功与失败都走 `finishRestore()` 写终态，**不存在**停留在 `RESTORING` 的正常路径；
- 失败时 `restored_keys` 记录已回放数量，异常消息带上"已回放 N 个键，数据可能不完整"。

### 4. 僵尸状态回收

进程崩溃会留下 `RESTORING`。与导出的 30 分钟僵尸策略一致：
超过 30 分钟的 `RESTORING` 在下次恢复/导出时被标记为 `FAILED`（消息"恢复超时未完成"），随后放行。

## 后果

- 恢复失败后备份仍可再次恢复（`restoreStatus` 从 `FAILED` 重新进入 `RESTORING`）；
- `GET /api/v1/backups` 返回恢复状态、耗时与已回放键数，前端无需新增接口即可展示；
- 仍**不保证原子性**：中途失败已写入的键保留。这是 ADR-0365 的既有语义，本 ADR 只让"失败"可被看见，
  不把它粉饰成可回滚。真正的原子恢复需要临时命名空间或快照机制，留待后续。

## 验证

`BackupServiceRestoreTest`（6 例，每例对应一条不变量）：

| 用例 | 不变量 |
| --- | --- |
| 两个并发恢复只有一个获得执行权 | 互斥成立（移除守卫后该用例失败，已实测） |
| 备份进行中拒绝恢复 | 跨操作互斥 |
| 恢复进行中拒绝导出 | 跨操作互斥（反向） |
| 恢复失败不污染备份状态且记录已回放数 | 状态分离 + 异常安全 |
| 失败后可以重试并成功 | 可恢复性 |
| 僵尸恢复状态可被回收 | 崩溃遗留可自愈 |

控制面全量回归：99 例通过、0 失败。

## 未覆盖

- 恢复与客户端 `SET` 的并发：控制面不拦截直连内核的写，本 ADR 不承诺隔离客户端直写；
- 恢复期间删除实例：实例删除与恢复的竞态未做专门测试；
- Flyway 迁移在真实 MySQL 上的执行：本次以单元测试验证行为，迁移脚本未经真实库执行。
