# ADR-0373：延迟统计的去监视器化（G0-5B-4 / F4）

- 状态：Accepted
- 日期：2026-11-07
- 关联：G0-5A F4、TD-096

## 背景

`LatencyStats.record()` 每条命令执行 `synchronized (current)`；`snapshot()` 每次新建一个直方图，
并在 `previous` 与 `current` 两把监视器下合并。高并发下 `current` 是所有命令的争用点，
INFO 又与写入争同一监视器。

## 统计语义（先定语义，再改实现）

| 问题 | 结论 |
| --- | --- |
| 每个样本恰好记录一次？ | 是；累计直方图与窗口直方图各记一次到各自的独立累加器 |
| 桶边界 | **不变**：17 个固定微秒上界（50µs…5s，+∞） |
| 分位数 | **不变**：桶上界估算，并以样本最大值封顶 |
| 快照是否严格同一时点？ | **否**，明确为近似快照；窗口合并期间的写入会计入相邻窗口之一，不重复计入累计 |
| 允许并发写入? | 允许；`LongAdder` 语义即可 |
| 重置 | 仅按 60 秒窗口轮转，不做显式清零 |

## 决策

1. `current`/`previous` 改为 `AtomicReference<LatencyHistogram>`；`record()` 只做两次 `LongAdder` 自增，
   **不获取任何监视器**；
2. 轮转（每 60 秒一次）才加锁：`getAndSet(new LatencyHistogram())`，旧窗口置为 `previous`；
3. `snapshot()` 读取两个引用后合并到**局部**直方图，不锁任何共享对象；
   因此仍有一次分配（17 个 LongAdder），但**不再有两次同步合并**；
4. 未采用"共享可复用数组"方案：多线程共同修改同一数组难以验证，正确性优先于零分配。

## 后果

- 写路径无监视器争用；
- 快照为近似一致（文档化），分位数语义与旧实现一致；
- 每次 `snapshot()` 仍分配一个直方图（INFO 频率低，可接受）；
- 轮转瞬间可能短暂出现"上一窗口为空"的情况，`snapshot()` 仍返回当前窗口数据。
