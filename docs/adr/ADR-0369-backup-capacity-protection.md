# ADR-0369：备份容量保护与预留

- 状态：Accepted
- 日期：2026-11-07
- 关联：G0-4、ADR-0367（保留与删除）

## 背景

`runExport()` 直接写最终文件：没有容量预检、没有临时文件、失败即留下半截文件。
两个控制面实例同时导出时，各自看到的剩余空间相同，可能同时判断"够用"并一起写满磁盘。

## 决策

### 1. 预留与文件系统结合，缺一不可

- **数据库预留**负责"并发任务之间的协调"：一行一条 `backup_reservation`，按存储路径求和；
- **文件系统查询**负责"真实可用空间"：`FileStore.getUsableSpace()`；
- 判定条件：`usable - 已预留 - 最小保留余量 >= 本次估算`。

数据库预留不能替代实际空间查询（会与实际磁盘脱节），实际查询也不能替代预留（并发下会超额分配）。

### 2. 估算保守

优先取该实例最近一次成功备份的实际大小 × 1.25；无历史时使用配置下限（默认 16 MB）。
估算只用于"是否放行"，导出完成后以真实文件大小回填。

### 3. 写入：临时文件 + 原子发布

写入 `xxx.jsonl.tmp`，成功后 `ATOMIC_MOVE` 到最终名；失败删除临时文件。
跨文件系统时 `ATOMIC_MOVE` 不可用，降级为普通 move 并记录告警（同目录下通常可用）。

### 4. 失败语义

| 情况 | 处理 |
| --- | --- |
| 预检不通过 | 记录直接置 `FAILED`，消息含"空间不足"，不创建文件 |
| 写入中途 ENOSPC | 删除临时文件，记录 `FAILED`，释放预留 |
| 成功 | 原子发布，回填真实大小，释放预留 |
| 进程崩溃 | 预留 30 分钟后过期回收；`.tmp` 文件由孤儿清理（G0-2）按宽限期删除 |

### 5. 与 G0-2 的边界

- 正在导出的记录（`RUNNING`）本就不在清理候选；
- 预留记录独立成表，孤儿文件清理不会触及；
- 清理后再次导出时重新读取真实可用空间，不依赖任何缓存估算。

## 后果

- 磁盘不足时**导出开始前**即拒绝（507），不再出现"写了一半失败"；
- 双实例同时导出时，第二条请求看到的可用空间已扣除第一条的预留；
- 仍不保证绝对不 ENOSPC（其他进程可随时写入），因此写入保护与临时文件清理必须同时存在。
